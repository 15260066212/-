# ADR-017: 内容审核流程（八维度评分 + AI 重写 + 多轮重审）

**Type:** ADR
**Status:** accepted
**Tags:** architecture, review, content-quality, ai

## Context

GEO 系统作为内容发布平台，需要在文章发布前进行质量审核。核心需求：

- **多维度评估**：文章质量不是单一指标，涉及合规性、SEO、品牌、可读性等多个方面；
- **AI 辅助审核**：利用 AI 模型自动审核，减少人工成本；
- **自动改进**：审核不通过时，自动重写改进而非直接拒绝；
- **多轮迭代**：首次审核不通过可修改后重新审核，最多 3 轮；
- **审计可追溯**：每轮审核的结果和修改都需记录，便于回溯。

## Decision

采用 `ContentReviewer` 八维度评分 + AI 重写 + 多轮重审的三阶段审核流程。

### 1. 八维度审核模型

`ContentReviewer` 对每篇文章执行 8 个维度的审核：

| 维度 | 说明 | 权重 |
|------|------|------|
| `compliance` | 合规性（违规词、敏感内容） | 高 |
| `quality` | 内容质量（信息密度、逻辑性） | 高 |
| `seo` | SEO 友好度（关键词、标题、结构） | 中 |
| `brand` | 品牌一致性（风格、调性） | 中 |
| `originality` | 原创性（抄袭检测） | 高 |
| `platform_adaptation` | 平台适配度（格式、长度） | 中 |
| `readability` | 可读性（段落、句子长度） | 低 |
| `safety` | 安全性（风险提示、免责） | 高 |

**评分方式**：每个维度独立评分（0-100），通过 `calculateWeightedScore()` 计算综合加权分。

### 2. 通过条件

审核通过需同时满足：

| 条件 | 阈值 | 说明 |
|------|------|------|
| 综合分 | ≥ 60 | 加权总分达到合格线 |
| 合规性维度 | 无高危 | `compliance` 不能有高危标记 |
| 平台适配维度 | 无高危 | `platform_adaptation` 不能有高危标记 |
| 安全维度 | 无高危 | `safety` 不能有高危标记 |
| 最低维度分 | ≥ 50 | 任一维度不得低于 50 分 |

### 3. 三阶段审核流程

```
阶段 1: 审核入口 (POST /api/review/:articleId)
  → 读取文章和会话数据
  → 实例化 ContentReviewer
  → 执行八维度审核
  → 计算综合分

阶段 2: 审核通过?
  → 通过: 更新文章状态为 reviewed, 返回审核结果
  → 未通过 + 轮次 < 3: 进入阶段 3
  → 未通过 + 轮次 >= 3: 标记为审核失败, 返回结果

阶段 3: AI 重写
  → 使用 ContentGenerator 根据审核反馈生成改进版本
  → 更新文章内容
  → 自动重新审核（回到阶段 1, reviewRound + 1）
```

### 4. 审核审计

每次审核结果记录到 `review_audit_logs` 表：

| 字段 | 说明 |
|------|------|
| `articleId` | 关联文章 |
| `round` | 审核轮次（1-3） |
| `reviewer` | 审核者（`ai` 或人工 ID） |
| `result` | 审核结果（通过/失败） |
| `scores` | 各维度得分 |
| `feedback` | 审核反馈（用于 AI 重写） |
| `createdAt` | 审核时间 |

### 5. AI 重写机制

`ContentGenerator` 根据审核反馈自动改进文章：

- **输入**：原文章 + 审核反馈（低分维度的改进建议）；
- **输出**：改进后的文章内容；
- **策略**：针对低分维度定向优化，不改变文章核心主题；
- **限制**：最多重写 3 次（对应 3 轮审核），避免无限循环。

### 6. API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/review/:articleId` | POST | 触发审核（自动多轮） |
| `/api/review/:articleId/result` | GET | 获取审核结果 |
| `/api/review/:articleId/history` | GET | 获取审核历史 |

## Alternatives Considered

### 替代方案 1：人工审核

**描述**：所有文章由人工审核，不使用 AI。

**否决理由**：人工成本高，审核速度慢，不适合规模化内容生产；AI 审核已能覆盖大部分常见质量问题。

### 替代方案 2：单一维度评分

**描述**：只计算一个综合分，不做多维度评估。

**否决理由**：无法定位具体问题（是合规问题还是 SEO 问题？）；AI 重写缺乏明确的改进方向。

### 替代方案 3：审核不通过直接拒绝

**描述**：不自动重写，审核不通过直接返回失败。

**否决理由**：AI 生成的内容常有微调空间，自动重写能显著提升通过率；直接拒绝浪费已生成的内容。

## Consequences

### 正面影响

1. **质量保障**：八维度评估覆盖文章质量的各个方面；
2. **自动化**：AI 审核 + AI 重写，全流程无需人工介入；
3. **可追溯**：每轮审核都有审计记录；
4. **渐进改进**：多轮重写逐步提升文章质量。

### 负面影响

1. **AI 成本**：审核和重写都消耗 AI Token，3 轮审核 + 重写成本较高；
2. **审核耗时**：多轮审核 + 重写可能耗时数分钟；
3. **维度权重硬编码**：权重目前固定，无法按平台或内容类型调整；
4. **AI 审核局限性**：合规性和原创性检测依赖 AI 判断，可能有遗漏。

### 需要跟进的事项

- [ ] 支持按平台配置维度权重
- [ ] 增加人工审核干预入口（AI 审核后人工复核）
- [ ] 原创性检测接入专业查重 API
- [ ] 审核结果结构化输出（便于前端展示）

## Superseded when

1. 引入专业查重或合规检测服务替代 AI 审核；
2. 审核维度需求超过 8 个，需要可配置化；
3. 审核流程从同步改为异步事件驱动。
